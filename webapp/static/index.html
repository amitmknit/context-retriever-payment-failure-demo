What this demo shows

Two Redis products working together on one problem. Context Retriever turns a data model over Redis-resident business data into a governed set of MCP tools an agent calls at runtime — no SQL, no direct database access. Agent Memory gives that agent conversation continuity and durable recall about a customer across sessions.

How the pieces fit

The agent never talks to Redis directly. It calls generated tools over MCP; Context Retriever executes the query against Redis. Agent Memory is a separate service the agent also calls.

Relationships are not inferred from field names

A tag field named customer_id does not auto-link to Customer. We tested this: a model relying on naming convention alone exported zero relationships. Each one must be declared explicitly with ContextRelationship(target=…, source_field=…).

Governance — and what we could not confirm

The access model as designed, plus the findings from testing it live. This section exists because a governance claim that has not been verified against the real service is a claim, not a control.

Two key types

Admin key

Provisions. Creates and updates the entity model on a surface. Should never be held by an agent.

Agent key

Invokes only tools that already exist. Cannot change the model. This is what the demo's agent holds.

Access-tag enforcement did not filter results in our testing

We created a second agent key scoped with access_tags={"tier": ["standard"]} and queried the enterprise-tier customer with it — directly by ID and via filter_customer. Both calls returned the restricted record, unfiltered. On this preview build, in this test, access tags did not act as a data boundary. Treat it as unverified until you have tested it in your own deployment.

Background promotion is aggressive

A single five-turn conversation produced 42 auto-extracted long-term memories, on top of the two we wrote deliberately — sometimes near-duplicates across promotion windows. Plan namespace and topic discipline before this reaches production volume. See Memory → Browse memory store for the live count.

The documented similarity threshold returned nothing

The Agent Memory docs suggest starting at 0.7. Against this store's real embeddings, 0.7 returned zero results for a plain-language query while 0.5 returned the expected records. Tune per workload; do not demo on the documented default untested.
